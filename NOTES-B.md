# Notes, family B
- Reciprocal measured against Go: mu == (2^512-1)/m for most m, but about 0.5% of random m give exactly one less. The spec must therefore be a relation (floor-1 <= mu <= floor), or the exact Newton model.
- U7 (kernel deep recursion): see /srv/janus-ops/UINT256-UPSTREAM.md; repro wip/Float64-arm64-u1repro.lean. Facts: top-level proof term depth 315, auxiliary lemmas pass individually; failure is inside kernel evaluation during the epilogue load after a callee's stores.
- Private tooling: tools-local/lean1.sh (direct lean run against the last verify workspace); the workspace under ~/.cache/janus/.../consumer is shared per consumer hash and gets overwritten by the last `tools/v.sh` of ANY ISA/function: rerun v.sh to restore Extracted.
- A single extraction contains the callees (udivrem, udivremKnuth, udivremBy1, math/bits.Div64) identical across Div/Mod/...; proofs of their summaries must be repeated per extraction (generate from one template).
- Division chain (amd64), all in lean/Fv256/Amd64/: By1Loop/DivWork (udivremBy1), Knuth{Sub,Add,Est,Ovf,Iter,Tail,Defs,Loop,Run,Entry,Summary} (udivremKnuth `knuth_summary`), Udivrem{A..K} (udivrem; `UdivremK.udivrem_summary` is the Summary that wrappers use with `janus64_run ... calls [..]`). Math: KnuthMathB, UdivMathB, UdivremMath (shared by the arm64 chain). Specs: SpecB2 (`divSpec`, `modSpec`), helpers UtilB2.
- udivrem_summary precondition (all derived from the code, not assumed): return address readable < 2^47; 0x150 <= RSP; `StackGuardOK s 0xf8`; `StackWritable s 0x148 0x48` (window [sp0-0x148, sp0+0x48): udivrem's frame plus the 8 spill slots of the caller; Go's spill area is exactly 8 words = 0x40, the extra 8 bytes are the rem pointer slot); X15 = 0; quot/u slices of length 4 (RBX = RSI = 4); quot, u, d, and (non-nil) rem buffers; d != 0; quot = 0 and rem = 0 on entry; the guard pointer outside the window. Post: `wv quot = U/D`, `wv rem = U%D`, frame, RSP/RBP/R14/X15 restored; post is phrased with explicit register/xmm functions (`fun i => if i = 4 ...`) because `janus64_run calls` only turns equations on state components into rewrite rules.
- `udivrem` lemmas depend on the exact stack layout (sf = sp0 - 0xf0): a change of any frame constant means recompiling Udivrem{B..K}; tightening the caller window from 0x50 to 0x48 was one sed + full recompile (about 40 min).
- MemFrame (Janus) is used in wrapper postconditions instead of Util.OnlyWrites2 because callee summaries give MemFrame and `janus_frame` proves it.
